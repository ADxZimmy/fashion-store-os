You are working inside an existing application currently built as Pastry County Kitchen OS. I want you to transform/adapt the spine of this app into a brand-agnostic Tailor/Fashion Business OS.

Do not rebuild from scratch unless absolutely necessary. First inspect the existing codebase, routes, components, state management, storage/database structure, business logic, and UI patterns. Then create a careful implementation plan using GSD and apply changes incrementally.

The goal is to reuse the existing app skeleton: dashboard, customer/order flow, inquiry management, inventory management, settings, records, analytics, and business operations logic, but adapt the domain from kitchen/food production to tailoring/fashion production.

Core product idea:
This should become a generic Tailor OS / Fashion Studio OS that any fashion designer, tailoring brand, garment maker, or fashion studio can use. It should not be hardcoded to Mo’ora Afrika or any specific brand. On first launch, the user should set up their business profile.

First-launch onboarding requirements:

* Show a business setup screen when no business profile exists.
* Capture business name, business type, logo upload if supported, phone, email, address, currency, preferred measurement unit, preferred fabric unit, and basic brand colors.
* After setup, the app should use the business name throughout the UI instead of any hardcoded brand name.
* Store this business profile persistently using the project’s existing storage/database approach.

Brand/appearance settings:
Add a simple Appearance/Branding settings section.
Allow the user to customize:

* Primary color
* Accent color
* Header/sidebar color
* Highlight/success color
* Background mode if supported
* Logo/business mark if supported
* Business display name

Use CSS variables/design tokens so the UI can change dynamically without rewriting every component. Remove hardcoded Pastry County brand colors/names and replace them with generic theme variables.

Domain conversion:
Replace kitchen terms with tailoring/fashion terms throughout the app where appropriate.

Examples:

* Recipes should become Style Recipes or Garment Recipes.
* Ingredients should become Materials.
* Menu/items/products should become Garment Styles, Pieces, or Services.
* Kitchen/prep flow should become Production Workflow.
* Food inventory should become Fabric & Materials Inventory.
* Event/catering orders should become Client Orders, Custom Orders, or Collection/Batch Orders.
* Production notes should become Tailoring Notes, Fitting Notes, Cutting Notes, or Finishing Notes.

6. Style Recipe / Bill of Materials system
   This is very important. Implement the tailoring equivalent of a recipe system.

A Style Recipe should define the estimated materials required for a garment. It should support fixed materials, measurement-based materials, and design modifiers.

Material calculation concept:
Style Recipe + Client Measurements + Fabric Width + Design Details + Wastage Allowance = Estimated Material Requirement

A Style Recipe should include:

* Base fabric requirement
* Fabric unit: yards/meters
* Supported fabric widths: for example 45 inches, 54 inches, 60 inches
* Fixed items: buttons, zippers, labels, packaging bags, hooks, snaps, etc.
* Variable items: main fabric, lining, interfacing/stay, elastic, trims, lace, thread, embroidery thread
* Wastage allowance percentage
* Size adjustment rules
* Design modifiers

Examples of design modifiers:

* Long sleeves: add extra fabric
* Short sleeves: reduce fabric
* Lining: add lining fabric
* Flared cut: add extra fabric
* Pleats/gathers: add extra fabric
* Embroidery: add embroidery material/time/cost
* Beading/stones: add embellishment quantity
* Collar/cuff/placket: add interfacing/stay
* Pockets: add fabric/interfacing
* Extra length: add fabric
* Heavy/full silhouette: add fabric

The system does not need perfect advanced pattern-making mathematics at first. It should support practical estimate rules that a tailor can edit.

8. Inventory reservation and deduction workflow
   Implement inventory in stages:

* When an order is confirmed, reserve estimated materials.
* When cutting begins or fabric is cut, deduct actual fabric used.
* If actual usage is less than estimated, release the unused reserved quantity.
* If actual usage is more than estimated, warn the user and deduct the additional amount.
* On production completion, deduct finishing items such as buttons, labels, zippers, packaging, etc.
* Track available stock, reserved stock, and used/consumed stock separately.
